# Trang "Plan cuộc đời" — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thêm trang mới `/life-plan` "Plan cuộc đời". Trang gồm ghi chép hằng ngày (có ảnh) và kế hoạch, tất cả trên một dòng thời gian có vạch "Hôm nay". Ảnh riêng tư lưu trên Cloudinary miễn phí.

**Architecture:**
- **Chữ** (ghi chép, kế hoạch) nằm trong localStorage `"life-plan-data"`. Data layer ở `src/lib/life-plan/`, theo khuôn của `work`. Sao lưu và đồng bộ đi qua `data-transfer.ts`.
- **Ảnh** được thu nhỏ trên trình duyệt, rồi đi qua API của app `/api/life-plan/images`, kiểm `Bearer SYNC_SECRET`. Server gọi REST API của Cloudinary với chữ ký SHA-1 và giữ link có chữ ký ở phía server.
- Ảnh đã tải về được giữ lại trong IndexedDB, mỗi máy chỉ tải một lần.

**Tech Stack:** Next.js 16 App Router (route handlers), React 19, TypeScript, Tailwind v4 (container queries), zod 4, Vitest + RTL. **Không thêm thư viện nào.**

**Spec:** `docs/superpowers/specs/2026-10-29-life-plan-design.md`

**Thứ tự `buildTimeline`:**
- `day` giảm dần.
- Cùng ngày thì kế hoạch đứng trước ghi chép; trong mỗi loại, `id` lớn đứng trước.

- `planFilter` khác null thì chỉ giữ kế hoạch đó và các ghi chép có `planId` trùng, vẫn kèm vạch `today`.

**Cách gọi Cloudinary** (kiểm lại với tài liệu Cloudinary khi có tài khoản thật):
- **`signApiParams`:**
  - sắp các cặp theo tên;
  - nối `k=v` bằng `&`;
  - nối thêm `apiSecret` vào cuối;
  - lấy SHA-1 hex bằng `node:crypto`.
- **Tải lên:** `POST https://api.cloudinary.com/v1_1/{cloud}/image/upload`, body multipart gồm:
  - `file`;
  - `public_id`: `{folder}/{20 ký tự [a-z0-9] ngẫu nhiên}`, sinh bằng `node:crypto` (`randomBytes` hay `randomInt`);
  - `asset_folder` bằng `folder`, để ảnh nằm đúng thư mục trong Media Library vì tài khoản mới dùng dynamic folders;
  - `type=authenticated`, `timestamp`, `api_key`, `signature`.

  Ký trên `asset_folder`, `public_id`, `timestamp`, `type`. Ánh xạ kết quả `{ public_id, bytes, width, height }` → `LifePlanImage`.
- **Xoá:** `POST …/image/destroy` với `public_id`, `type=authenticated`, `timestamp`, `api_key`, `signature`. Ký trên `public_id`, `timestamp`, `type`. Xoá được khi kết quả là `{ result: "ok" }` hoặc `"not found"`.
- **Xem:**
  - `signedDeliveryUrl` có dạng `https://res.cloudinary.com/{cloud}/image/authenticated/s--{sig}--/{publicId}`;
  - `sig` là 8 ký tự đầu của base64url(SHA-1(`publicId` + `apiSecret`));
  - server `fetch` link này rồi trả bytes về trình duyệt.

**Các route:**
- **`POST /api/life-plan/images`:**
  - chạy `checkSyncSecret` trước;
  - thiếu config thì 503;
  - thiếu `file`, `file` không phải `image/*`, hay file lớn hơn 4MB thì 400;
  - thành công thì 201 kèm `LifePlanImage`;
  - Cloudinary lỗi thì 502 `"Không tải được ảnh lên. Vui lòng thử lại."`.
- **`GET ?id=`:**
  - `checkSyncSecret`; `id` không bắt đầu bằng `life-plan/` thì 400; thiếu config thì 503;
  - lấy bytes từ link có chữ ký, upstream 404 thì 404;
  - trả `Content-Type` theo upstream và `Cache-Control: private, max-age=31536000, immutable`.
- **`DELETE ?id=`:** cùng các bước kiểm như `GET`, rồi `destroyOnCloudinary` → `{ ok: boolean }`.
- **`GET /api/life-plan/images/status`:** không cần khoá, trả `{ configured: cloudinaryConfig() !== null }`.
